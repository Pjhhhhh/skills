# 工作流程

修改既有文件时，以当前内容为基线，只改变任务要求及必要关联内容，保留受保护部分。

## 先判断任务分支

- 纯问答、状态查询和流程讨论：按宿主当前有效的全局要求直接回答。研究或交付后的追问沿用仍有效的结论；新增、加强或改变条件的关键判断按[主张核查](references/execution-and-recovery.md#主张核查)核对依据。
- 受委派的只读调查或评审：按父任务约定返回结论、证据位置和待验证项，由父代理保存并核对整体结果。明确选用记录检查 CLI 时采用其 JSON 格式。
- 简单实质任务：目标和授权明确、影响可控、终态可直接核验且证据一致时，直接执行并保存必要结果。
- 复杂任务：需要多阶段探索且终态无法直接核验、必须跨阶段保留长上下文或状态才能完成必要验收、存在关键证据冲突，或涉及高影响且难回退的变更。沿用相关计划和必要证据，按实际依赖与风险安排核验。

按必要结果的风险、依赖关系和终态可核验性分流，完整满足当前要求；任务复杂度变化时采用对应分支。

需要确定计划、任务记录的位置或恢复原任务时，读取[任务位置与记录](references/execution-and-recovery.md#任务位置与记录)。

## 按实际要求核验与交付

1. **明确结果与验收。** 从原请求、有效纠正和专项技能中确定必要结果、职责与权限。实施前将必要结果对应到可观察的通过条件、能检出不满足的检查方式及证据来源；简单任务直接利用已有上下文，探索任务随已核实事实细化判据，保留有效原目标与纠正依据。将用户已给的失败例、必要调用场景与检查范围纳入验收目标，在已有材料中保留依据。涉及已定业务决定或新增条件时，按[需求确认与实施边界](references/execution-and-recovery.md#需求确认与实施边界)核对有效回答及依据。
2. **选用必要方法。** 需要工程诊断、规格与任务安排、按规格实施或规范与规格审查时，按[Matt Pocock接入规则](references/matt-pocock.md)选择技能；需要驱动实际应用、生成或维护验证入口、性能测量、变更影响或约束反复错误时，按[pstack接入规则](references/pstack.md)选择技能。只读取当前需要的分支，将专项结果用于本任务的执行与验收。新建或调整可复用检查、评分器，或发现漏检、误拒及判断冲突时，按[检查校准](references/execution-and-recovery.md#检查校准)核验受影响的判据。
3. **执行并验证。** 功能、接口、配置、操作方法或技能发生变化时，同步核对并更新受影响的现行文档，将文档与最终行为一致纳入必要结果。实施期间按项目策略检查；完成实现与自检后，按[业务验收](references/pstack.md#业务验收)经真实用户入口核验必要功能、终态与副作用，失败时回修并重验。其他任务直接打开交付物、读取实际字段或状态，运行相应真实行为检查。有原型、模板、规格等原始对照依据，承诺多对象一致性，或分析相互关联资料时，读取并按[主张核查](references/execution-and-recovery.md#主张核查)核对参考与实际结果、覆盖范围及结论。生成文件修改源后重新生成；打包、服务及外部调用按现有授权执行。耗时工具转后台或需要取消、重试时，按[后台执行与恢复](references/execution-and-recovery.md#后台执行与恢复)接回实际任务；修改规则、技能或运行配置及升级第三方组件时，按[生效状态与配置升级](references/execution-and-recovery.md#生效状态与配置升级)核对受影响的加载状态。
4. **按需要复核。** 用户或项目明确要求，或存在高影响、难以恢复、关键证据冲突时，安排只读独立复核。评审者直接读取原要求、有效纠正、当前工件与原始证据，自行确定必要结果，检查作者清单之外的遗漏；作者解释用于定位问题，需要时读取源码、差异和执行轨迹。按[主张核查](references/execution-and-recovery.md#主张核查)核对验收目标、实际检查与证据的对应关系。继续处理可修问题，判据问题按[判据更正](references/execution-and-recovery.md#判据更正)核实并复验。
5. **按实际结果交付。** 结束执行任务前，读取并完成[主张核查](references/execution-and-recovery.md#主张核查)，依据核对后的必要范围和实际证据判断完成状态。形成实际待交付答复后，核对其中新增、加强或改变条件的关键结论；已审工件的结果仅支持对应对象、版本与范围。可推进的缺口按[回修与跨轮恢复](references/execution-and-recovery.md#回修与跨轮恢复)继续处理，必要结果及检查完成后交付。交付时说明仍影响使用的失败或未完成项。沿用有效证据，变化使结论失效时复验相关内容。必要独立复核暂时无法执行时，保留具体原因、未完成状态与恢复条件。执行已获授权的提交或推送前，按[Git 提交与推送范围](references/execution-and-recovery.md#git-提交与推送范围)核对共享内容和实际操作范围。

用户要求复盘，或出现已证实的漏验收、重复纠正、验证入口失效等方法问题时，按[会话复盘](references/matt-pocock.md#会话复盘)查明原因并提出改进；当前任务的必要验收继续完成。

失败、待验证或评审分歧按[回修与跨轮恢复](references/execution-and-recovery.md#回修与跨轮恢复)处理。来源或结论存在不确定性时，按[如何处理“不确定”](references/execution-and-recovery.md#如何处理不确定)核对证据及受影响动作。

交付工件或修订既有结果时，按[交付位置与修订](references/execution-and-recovery.md#交付位置与修订)核对实际使用者、用途、有效工件和可用入口。测试结束时，按[测试产物收尾](references/execution-and-recovery.md#测试产物收尾)核对保留内容、清理范围及引用。

默认直接核验实际结果，沿用已有计划、必要日志和交付物。显式选择记录检查 CLI 时，再读[功能入口](references/cli-reference.md)和[输入协议](references/record-checking-protocol.md)，按其要求准备和核对记录。

## 工具选用与协作

按任务需求、交付格式与可编辑性选择工具，复用已有实现、图源和证据，按需要组合互补能力。用户指定、项目要求或当前能力缺口需要其他技能、插件及 CLI 时，查[可选接入说明](references/optional-integrations.md)。处理长材料、截断输出或交接时，采用[长输出与摘要](references/execution-and-recovery.md#长输出与摘要)的读取方法。

可独立推进且并行有收益时，在已有授权内分配执行者。主会话提供原始要求、有效纠正、目标、权限边界、必要验收和上下文，明确读写路径、产物与依赖。分配实施、恢复或接手时，按[需求确认与实施边界](references/execution-and-recovery.md#需求确认与实施边界)一并传递决定状态与原始依据。共享目标顺序写入，上下文继承方式按任务需要选择。

执行者完成授权工作与自检，在阶段变化或受阻时报告实际进展，返回结论、工件位置、必要版本信息、证据及未完成项。主会话核实返回结果，处理子任务之间的依赖，补齐整体结果所需的检查与证据，负责最终交付；可修问题交回具体目标与依据。
