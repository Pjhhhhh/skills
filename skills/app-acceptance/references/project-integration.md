# 项目接入与真实样例

## 复用项目事实和入口

通用验收方法由本技能维护。项目保留当前启动及测试命令、环境与版本检查、路由／选择器、接口契约、数据源、业务规则、功能地图、文件解析和资源归属。直接读取项目已有验证文档、package scripts、测试配置及执行器即可；已有 `verify-<app>/SKILL.md` 也可作为事实和命令入口。

项目无需为采用本技能另外建立本地技能。确需新建或维护可重复入口时，沿项目现有结构补必要脚本和文档；可用的 create-verification-skill／maintain-verification-skill 按其职责选用，未安装时继续已有可执行路径。迁移旧项目技能中的通用说明与保留项目事实需有明确范围和依据，不能据采用本技能自动删除旧文件。

已有命令只覆盖本轮部分结果时，补必要观察或断言；按当前需求选择旅程及受影响回归。功能地图帮助定位，不自动把全部已有功能变成本轮门槛。项目没有可运行环境时，继续独立可做检查，保留依赖该环境的具体未验项及恢复条件。

## 项目自己的验收流程

用户明确要求建立或完善流程，或项目缺少可靠入口且当前工作需要重复验收时，按下面顺序形成该项目能继续使用的说明和必要脚本。已有可靠流程定向补缺即可。

1. **调查项目事实。** 从有效业务要求、原型及用户最新纠正确定预期；读取运行文档、依赖配置、路由／公开接口、测试和现有工具，核对技术栈、真实入口、启动与就绪条件、环境版本、数据前提、外部依赖和操作权限。可观察的技术事实自行查明，只询问材料中无法确定的业务决定、真实环境信息或授权缺口。
2. **沿用项目归属。** 复用既有文档、package scripts、Makefile、测试目录、功能地图或项目技能，使用者能从正常项目入口找到方法即可。目录、文档格式和地图粒度按项目需要选定；项目技能只在明确采用该形态时建立。
3. **写清场景与判据。** 按当前要求记录必要场景及需求依据、前提与数据边界、实际入口和命令、预期终态及副作用、应保存和读回的证据、失败归因与同项复验、资源归属与回收。相应场景先核必要对象存在及覆盖，合法空态另有明确预期；从规格或可信样本确定预期，避免按实现重新计算一遍作为断言。
4. **按说明实跑。** 在已授权环境执行覆盖新建或调整入口的完整必要场景，核实际请求、终态、工件及本轮资源回收；有已知失败或明确失败机制时，用对应反例证明同项判据能拒绝，再以正常输入复验。其余必要场景按真实覆盖记录；一次入口实跑只证明该入口可用，当前业务任务仍须完成自身全部必要验收。

## 环境与副作用

先核项目实际加载点及可归属的运行资源。共享实例适合已获授权的只读观察；数据准备、写入、发送及故障注入采用获准的独占数据或明确边界。不能隔离时，按该项目实际约束执行与报告，不自行换成伪造来源证明真实效果。

“查询”或“打开统计页面”也可能自动保存快照；只读边界依据实际业务副作用，不能按操作名称或GET／POST方法简单判断。按当前风险核实动作是否写数据或发送，再选择可执行路径；不要求所有项目增加网络拦截。

## 按对象观察

| 当前范围 | 必要证据与容易遗漏的终态 |
| --- | --- |
| 前端表现／交互 | 当前实际页面、默认入口及需要的次视图；必要控件和语义结构；交互、焦点、展开及适用窄屏；有参考一致性要求时，同视口、主题、缩放、侧栏与加载状态比较实际内容边界和对应角色。 |
| 后端API／CLI／作业 | 实际入口、请求输入、响应和错误；必要字段、状态及与请求绑定的结果。写入或作业完成后独立读回必要存储、状态或文件，不以成功响应替代终态。 |
| 前后端联调 | 从真实用户操作追到实际HTTP及当前版本结果，刷新或回访仍保持必要对象、期间和版本。业务允许的空态与准备好的历史正数各自支持结论。 |
| 文件／导出 | 实际下载及解析／渲染后的字段、记录、公式或版式；核全量与筛选边界、同一数据版本及回收后原件可读。 |

检查集合前先确认其存在与要求覆盖。空记录列表可以合法，表头、查询条件等必要结构仍需观察。多对象承诺按对应对象和状态实看；共享源码、外壳同宽或某个控件正确只支持各自的观察。

## 接入必要集合助手

下面片段插入项目现有Playwright旅程，路径按实际技能安装位置传入；浏览器、运行环境和原生断言仍由该项目拥有。

```javascript
const { forEachRequired } = require('<技能目录>/scripts/required-collection.cjs');
const headers = page.locator('table[aria-label="记录列表"] thead th');
await forEachRequired(headers, '记录列表表头', async header => {
  expect((await header.innerText()).trim()).not.toBe('');
});
expect(await headers.allTextContents()).toEqual(['编号', '记录名称']);
```

助手空集合或隐藏项直接抛错，回调失败原样传播。它不推导业务列名、等待业务准备或代替精确覆盖断言；上述列名仅属于随包样例。等待实际数据／字体／布局稳定与验证期望是两个步骤，期望值本身不能充当等待结束条件。

已知漏检以同一必要断言区分正常与坏例。坏例因依赖缺失、服务未启动或浏览器不可用失败，表示环境未满足；只有失败落在预期对象或持久终态，才证明该项检查检出了坏例。实际业务FAIL和检测自检成功分别记录。

复杂或曾漏检的多阶段旅程，在正式结论入口核对预先确定的必要范围、实际执行与终态，以及本轮必需工件。采用故障注入检验判据时，同时保留目标确实变为预期坏状态的证据；未命中或未破坏目标语义的运行单独记录。

## 运行随包样例

要求本机已有Node.js、Python 3、Playwright模块及其Chromium浏览器。使用已有依赖，不自动安装或下载。下面变量由调用者填入新的绝对路径，父输出目录需已存在；子进程继承调用者设置的临时目录。

```sh
skill_dir='<已安装app-acceptance的绝对目录>'
task_tmp='<本任务临时根绝对路径>'
run_output='<不存在的新绝对输出目录>'
playwright_module='<已有playwright或@playwright/test模块的绝对路径>'
TMPDIR="$task_tmp" TMP="$task_tmp" TEMP="$task_tmp" \
node "$skill_dir/scripts/verify-example.cjs" \
  --output "$run_output" --playwright-module "$playwright_module" --case all
```

`--help`只显示参数；`--case`接受`healthy`、`missing-header`、`lost-write`和`all`，默认`all`。已有输出目录拒绝覆盖。服务绑定127.0.0.1动态端口，运行器持有并回收自己的Python进程和浏览器，原始证据保留。

| 场景 | 实际业务结果 | 检测自检要求 |
| --- | --- | --- |
| healthy | 默认空态保留两列表头，新增→POST→刷新→独立GET／持久文件→CSV完整链PASS | 正常检查通过，回收及原件读回完成。 |
| missing-header | 同一集合助手在记录表头处FAIL | `required-headers`阶段出现“必要对象集合为空：记录列表表头”。 |
| lost-write | POST201、页面暂显，独立GET没有受理记录，FAIL | `persistence-readback`阶段出现“持久终态缺少已受理记录”。 |
| healthy-recovery | 新数据目录上用同一断言完整PASS | 判据未降低、坏例没有污染恢复链。 |

单场景按实际结果退出：正常成功为0，坏例实际失败为1，参数或依赖错误为2。`all`顺序执行上表四例，`result.json`保留每例的`scenarioStatus`和单独的`expectedOutcomeObserved`；仅正常链通过、两个坏例在对应断言失败、恢复链通过且证据及回收完成时，`selfCheckStatus`为PASS并退出0。坏例自身始终保留FAIL。

每例包含版本／PID／URL、网络原件、Python日志、请求审计、持久JSON、截图、trace和适用的CSV。失败保留已完成动作及具体断言；回收不删除证据。本样例证明所用环境下这些检查实际可执行，不代表所有框架或目标项目已经通过。

### 独立控制器启动

前向试用或只验后端时，可由控制器启动服务，再向执行者提供实际loopback地址与公开契约。指定数据目录须不存在；模式只用于受控坏例，健康接口不披露模式。

```sh
python3 "$skill_dir/assets/example-app/server.py" \
  --data-dir '<新的绝对数据目录>' --mode healthy --port 0
```

启动stdout首行JSON给出`url`、`pid`、`version`、`mode`、`dataDir`。公开契约为`GET /health`返回版本和PID，`GET /api/records`返回`{"records": []}`；`POST /api/records`接受`{"name":"记录名称"}`，名称去首尾空白后1至80字符，成功201返回`{"id":"UUID字符串","name":"记录名称"}`，输入无效400；`GET /api/records.csv`下载UTF-8的`id,name`两列CSV。健康模式写入`dataDir/records.json`；`lost-write`模式保持同一成功响应但不持久化；请求审计在`dataDir/http.jsonl`。控制器按自己持有的进程句柄结束服务，数据和审计继续保留。

## 方法取舍

采用[Matt TDD](https://github.com/mattpocock/skills/blob/main/skills/engineering/tdd/SKILL.md)中从规格独立确定预期、经公开边界观察行为的思路；[规范与需求分别核对](https://github.com/mattpocock/skills/blob/main/skills/engineering/code-review/SKILL.md)使规范检查和业务符合性各自保留依据。原型及用户有效纠正仍参与验收，运行与数据终态按当前任务的必要证据核对。

采用[pstack项目验证方法](https://github.com/cursor/plugins/blob/main/pstack/skills/create-verification-skill/SKILL.md)的仓库事实调查，以及Launch／Doctor／Drive／Evidence／Cleanup所涵盖的启动、健康、驱动、证据与回收责任，用功能地图定位路径，并实际证明新增入口可用、变化后按范围维护。项目保留原生文档和工具；执行、必要询问、产物形态与维护范围由当前任务和授权决定。
