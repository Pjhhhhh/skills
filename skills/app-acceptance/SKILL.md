# 应用验收

从当前有效要求确定必要结果，执行本轮真实路径，核对终态与副作用。可独立使用；由 work-eval 统筹时承接其业务验收分支。

## 执行与完成

1. **确定必要结果。** 读取原请求、最新纠正及适用原型页面和功能说明，区分必要行为、合法空态、示例和未决选择。再用项目文档、源码、路由或功能地图定位执行入口；实现新增的步骤或前提回查有效依据。驱动前按必要结果确定数据前提、用户动作、预期终态与副作用、对应检查和证据来源；范围及判据覆盖本轮要求和已给失败例。
2. **核对实际运行。** 采用项目已有启动、健康及版本检查，确认当前进程、服务或构建，以及相关来源、存储、模型和外部发送模式。准备数据、写入、启动与回收按实际副作用及已有授权执行；测试证据只支持相应环境层级。
3. **驱动对应入口。** 本轮需要的正常首入、历史回访与带参路径分别观察。前端验证实际页面和交互；后端验证真实公开API、CLI或作业入口；联调连接用户操作、实际请求和同版结果。写入后独立读回必要持久状态，导出后解析或打开实际文件。纯前端表现或纯后端范围按其必要结果执行。
4. **先存在，再比较。** 依据要求确认必要表头、控件、字段、接口成员或导出记录存在且覆盖完整，再逐项检查属性和语义。合法空数据核明确空态，必要结构仍检查。异步加载按实际稳定条件结束，再独立判断预期。有一致性要求时，同条件实看参考与目标的对应语义角色和必要状态。
5. **检验判据。** 新增或调整可复用检查时，先确认已知正确输入能够通过。已知缺陷或漏检保留旧输入或受控坏例，确认目标确实形成预期坏状态，且检查在对应必要断言拒绝它；缺少必要观察时保留未验。回修后采用相同有效判据复验，判据更正保留要求依据与原失败。依赖、启动或环境失败单独报告，不能当作成功检出业务坏例。条件未变化的有效正常与坏例结果继续复用。
6. **按覆盖交付。** 对照必要结果、实际动作、终态、副作用与原始证据，区分通过、失败和未验；可推进的必要问题继续回修。缺对象、空循环、未执行或缺证不能算通过。回收自身资源后读回必要工件，复用未受影响的有效结果。独立复核条件按当前用户与项目规则，不由本技能额外扩大。

## 接入项目

接入已有项目文档、脚本或测试、判断只读与写入边界、选择UI／HTTP／持久状态／文件检查，或使用本技能样例时，读取[项目接入与真实样例](references/project-integration.md)。项目可直接保留验证文档、功能地图和执行器；已有 `verify-<app>` 技能也可兼容，不要求每个项目维护一层本地技能。

用户明确要求建立或完善项目验收流程，或缺少可靠入口且需要重复验收时，按参考中的[项目自己的验收流程](references/project-integration.md#项目自己的验收流程)调查事实、沿既有归属完善步骤与判据并实跑。已有可靠流程优先复用，普通一次验收直接按上面的必要路径执行。

## 必要集合助手

Playwright 旅程需要复用非空、可见和逐项等待检查时，按[接入必要集合助手](references/project-integration.md#接入必要集合助手)导入附带助手。精确业务覆盖和合法空态继续使用项目判据；其他框架采用等价存在性检查。助手与[随包样例](references/project-integration.md#运行随包样例)的验证范围是可复用检查及本技能自检。
